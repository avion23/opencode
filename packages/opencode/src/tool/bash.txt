Execute bash commands in a persistent shell with optional timeout. Use the `workdir` parameter for directory changes; never use `cd <dir> && <command>`.

For terminal operations (git, npm, docker) only. Use specialized tools (Glob, Grep, Read, Edit, Write) for file operations, not Bash.

Before creating directories/files, verify the parent exists. Always quote paths containing spaces.

Provide 5-10 word descriptions for each command. Run independent commands in parallel; chain dependent commands with '&&'. Use ';' only when you don't care if earlier commands fail.

Output is truncated automatically; don't use head/tail to limit it.

# Strategic Use

1. **Verification**: Primary tool for testing, linting, building. Prove code changes are correct.
2. **Environment**: Use for git operations, package management (npm, pip, go mod), project scripts.
3. **Utility**: File system navigation (ls), but prefer specialized tools (Read, Glob) for content.

# Protocol

- Do not ask permission for standard commands (`git status`, `npm install`, `pytest`).
- Chain dependent commands with `&&`.
- Run independent verification steps in parallel.
- **CRITICAL**: Do not use `echo` to communicate with the user.

# Operating Boundaries

## Workspace Scope
- Execute all commands within the current project workspace ONLY
- Scope file operations to specific project subdirectories (never root / or system paths)
- Use workdir parameter for directory changes; never use cd into system directories

## Permitted Operations
**Always Allowed:**
- Read: ls, cat, grep, find (within workspace)
- Git read: status, log, diff, show
- Build/test: npm install, bun test, cargo build
- Dev tools: docker, git clone, curl (downloads)

**Requires User Request:**
- Git history changes: rebase, reset --hard, push --force
- Branch deletion: git branch -D
- System-wide changes: git config --global, global npm packages
- Destructive operations outside project directory

**Always Confirm First:**
- Commands affecting production systems
- Operations on shared branches (main, master)
- Deletion of critical config files
- Any operation not explicitly requested

## Pre-Execution Checklist
Before executing:
1. Verify scope is limited to project workspace
2. Confirm operation is requested or standard development
3. For destructive operations, state rationale and impact
4. When in doubt, ask for confirmation

# Workflows

## Commit
1. Run git status, git diff, git log in parallel
2. Draft commit message focusing on "why" not "what"
3. Do not commit secrets (.env, credentials.json)
4. Stage, commit, verify with git status

## Pull Requests
Use gh command for ALL GitHub tasks (issues, PRs, checks, releases).

When creating PRs:
1. Run git status, git diff, check remote tracking, git log in parallel
2. Analyze ALL commits and draft PR summary
3. Create branch if needed, push with -u, create PR using `gh pr create`
4. Return PR URL
